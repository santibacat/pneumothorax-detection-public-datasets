# Datasets: expected folder layout

All datasets live in their own sub-folder of a single root folder. The root is given by the `CXR_DATASETS_PATH` environment variable (or `DATASETS_PATH` in [`cxr/config.py`](../cxr/config.py)), and the sub-folder of each dataset is defined in the same file (`NIH_PATH`, `CHEXPERT_PATH`, ...). **Folder names must match `config.py`**; edit it if yours are different.

The datasets are not redistributed. Sources for the public ones that need no explanation: [NIH ChestX-ray14](https://nihcc.app.box.com/v/ChestXray-NIHCC), [CheXpert](https://stanfordmlgroup.github.io/competitions/chexpert/), [MIMIC-CXR-JPG](https://physionet.org/content/mimic-cxr-jpg/2.0.0/), [PadChest](https://bimcv.cipf.es/bimcv-projects/padchest/), [VinDr-CXR](https://physionet.org/content/vindr-cxr/1.0.0/), [SIIM-ACR (Kaggle)](https://www.kaggle.com/c/siim-acr-pneumothorax-segmentation), [BRAX](https://physionet.org/content/brax/1.1.0/) and [Indiana / OpenI](https://openi.nlm.nih.gov/). CANDID-PTX, CRADI and PTX-498 are cited in the paper. Several of them (MIMIC-CXR, VinDr-CXR, BRAX, PadChest, CheXpert) require registration or credentialed access.

## How a dataset is loaded

Every dataset is a class in [`cxr/cxr.py`](../cxr/cxr.py) (`NIHDataset`, `CheXpertDataset`, ...). `ds.load()` first looks for a cached `processed_dataset.csv` inside the dataset folder. If it is not there, it reads the original metadata files listed above and preprocesses them (`load_dataset()` + `preprocess_dataset()`); `ds.save_processed_dataset()` writes the cache so later loads are fast.

All loaders produce the same `ds.df` columns, including `dataset`, `patient_id`, `study_id`, `patient_uuid`, `study_uuid`, `cxr_projection`, `pneumothorax`, `support_devices`, `no_finding`, `filepath` and `test_split`. `filepath` is the absolute path of the image on your machine. The files in `splits/` store the same path **relative to the root folder**.

## Things to check when something does not load

- **Folder names.** They must match `cxr/config.py`. In particular, CheXpert paths are resolved from the parent of the dataset folder (the CSVs start with `CheXpert-v1.0/...`), so that folder must be named exactly `CheXpert-v1.0`, and MIMIC-CXR must be at `MIMIC-CXR-JPG/2.0.0/`.
- **Files that are not part of the original datasets.** Besides the original files, the dataset folders used here contain files created locally. If you start from the original downloads you need to create the equivalent ones:
  - `VinDR-CXR/png/<image_id>.dicom.png` (PNG conversion of every DICOM in `train/` and `test/`) and `VinDR-CXR/annotations/dataset_as_png.csv`.
  - `CANDID-PTX/14909820/dataset_png/<SOPInstanceUID>.png` (PNG conversion of the DICOMs in `dataset/`) and `candid_ptx_metadata.csv` (generated by the loader).
  - `PTX-498/ptx498_metadata.csv` (generated by the loader from the `SiteA/B/C` folders).
  - `indiana/indiana_frontal_final.csv` and `indiana_lateral_final.csv` (list of frontal and lateral images; provided separately from the OpenI image and report release).
  - `processed_dataset.csv` caches (CheXpert, VinDr-CXR, BRAX, CRADI, Indiana and SIIM-ACR in the author's copy), written by `ds.save_processed_dataset()`.

  **DICOM to PNG conversion.** The conversion is implemented in the package: `VinDrCXRDataset.convert_dicom_to_images(output_dir)` and `CANDIDPTXDataset.convert_dicom_to_images(output_dir)` in [`cxr/cxr.py`](../cxr/cxr.py). For every DICOM it inverts `MONOCHROME1` images, applies the DICOM window (center and width, first value if there are several), applies the rescale slope and intercept, min-max normalizes to 8 bits and saves `<dicom file name>.png` in `output_dir`. It also changes `ds.df["filepath"]` to point to the PNGs, so call `ds.save_processed_dataset()` afterwards and later `ds.load()` calls will use them. The calls used by the authors were:

  ```python
  import os
  from cxr import cxr

  ds = cxr.VinDrCXRDataset(); ds.load()   # file paths point to the DICOMs in train/ and test/
  ds.convert_dicom_to_images(output_dir=os.path.join(ds.dataset_path, "png"))
  ds.df.to_csv(os.path.join(ds.dataset_path, "annotations", "dataset_as_png.csv"), index=False)

  candid = cxr.CANDIDPTXDataset(); candid.load()   # file paths point to the DICOMs in dataset/
  candid.convert_dicom_to_images(output_dir=os.path.join(candid.dataset_path, "dataset_png"))
  ```

  SIIM-ACR uses the Kaggle PNG version of the dataset (no conversion needed).
- **Cached and generated CSV files.** These files store the `filepath` column, and a file copied from another machine contains paths that do not exist on yours; delete it so the dataset is rebuilt from the original files. The SIIM-ACR classification file `segmentation/pneumothorax_siim_clasification.csv` is **not** generated automatically and is **not included** in this repository: it was derived from the dataset's `train-rle.csv`, with the columns `ImageId`, `EncodedPixels`, `pneumothorax`, `test`, `filepath`, `filesize` and `yolo_mask`. Without it (or a cached `processed_dataset.csv` in the SIIM folder), SIIM-ACR cannot be loaded.
- **Matching with `splits/`.** The relative paths in `splits/` are written as `<dataset folder>/<path inside it>` (for example `nih/images_001/images/00000002_000.png`), which is why the folder layout above matters. The helper `relative_path` in [`notebooks/00_quickstart.ipynb`](../notebooks/00_quickstart.ipynb) strips everything up to a folder named `ds-CXR/`; if your root folder has another name, adapt that line (or remove your `DATASETS_PATH` prefix instead).
